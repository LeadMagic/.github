# GitHub descriptions, README links, and attribution

Use a distinct, descriptive title and opening paragraph for each repository. Name the integration and the supported task in plain language. Keep installation instructions near the top, use meaningful link labels, and link to related projects where they help readers choose an integration. GitHub topics should describe the actual platform, protocol, and use case.

## Link tracking

Tag navigational links to LeadMagic website pages with:

- `utm_source=github`
- `utm_medium=readme` for README links; `referral` for repository About links
- `utm_campaign=<repository-name>` (`github` for the organization profile repository)
- `utm_content=readme-<section>` or `repository-about`; organization profile placements start with `profile-`

Use lowercase values and hyphens. Preserve existing non-UTM query parameters and fragments. Keep API endpoints, MCP service URLs, commands, downloads, image assets, GitHub links, and third-party URLs free of these tracking parameters. Never place personal data, credentials, customer identifiers, or account details in tracking values.

These parameters attribute visits if the destination analytics captures them; they do not establish conversion reporting or improve ranking by themselves. Keep website canonical URLs free of campaign parameters. Website analytics and canonical configuration are managed separately from these repositories.

## Maintenance

Verify linked pages, local paths, and published package contents. Update generated READMEs through their source generators. Prefer links to current pricing and entitlement documentation over duplicated plan tables. Keep archive notices prominent and avoid implying active support or third-party endorsement. Do not add keyword lists, fabricated badges, performance promises, or unverified compatibility claims.
